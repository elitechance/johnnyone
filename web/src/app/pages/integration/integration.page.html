Partner API — Integration Guide

JohnnyOne Partner API

Drive JohnnyOne programmatically — no UI. Create and control AI/terminal sessions and planner/development runs, and stream live terminal output.

Base URLs use the real worker domain that serves this page — {{ base }}. All traffic is over TLS. (For dev live validation use the johnnyone-dev worker domain.)

Two transports

The API is reachable over two transports. Pick by what you're doing — both authenticate the same way (see Access).

TransportUse it for
GraphQL {{ base }}/graphql Login, session lifecycle CRUD, planner/development lifecycle CRUD, API-key management, listing nodes & tools.
WebSocket {{ wsBase }}/api/relay/ws Live terminal I/O — subscribe to screen updates, send input, resize, kill.

Your account is a dedicated service account (one tenant + user). JohnnyOne hosts the desktop runtime for you — you never install anything. The server resolves your desktop node from your token; you never supply a node id.

Access

Every call — GraphQL or WSS — carries a Bearer credential. There are two kinds of credential, and either one works on both transports. The credential you use (JWT vs API key) and the transport you call (GraphQL vs WSS) are independent choices:

CredentialWhat it isLifetimeWorks on
Authentication (JWT) Your login access token — your account identity. Short-lived; renew with refreshToken. GraphQL + WSS
API key (jk_…) A long-lived machine (M2M) credential you mint, with explicit scopes. Long-lived; until revoked / optional expiry. GraphQL + WSS

Send either as Authorization: Bearer <value> on GraphQL and on the WSS upgrade — or as ?token=<value> on the WSS URL for browser clients that can't set headers. A partner needs one of these, not both.

1 · Authentication (login → JWT)

Log in once to get a short-lived accessToken (JWT) and a longer-lived refreshToken. Use this when the partner authenticates with their service-account credentials. 

curl -s {{ base }}/graphql \
  -H 'content-type: application/json' \
  -H 'x-tenant-id: your-tenant' \
  -d '{"query":"mutation($i:LoginInput!){login(input:$i){accessToken refreshToken}}",
       "variables":{"i":{"email":"you@partner.com","password":"…","tenantId":"your-tenant"}}}'

Then send it on every call: Authorization: Bearer <accessToken>.

Token lifetime. Access tokens are short-lived. When one expires, call refreshToken(input: RefreshTokenInput!): AuthPayload to get a new pair (returns { accessToken refreshToken ... }). A WebSocket authenticates once at upgrade — if the token expires mid-connection, reconnect with a fresh token (see Errors & limits).
?token= fallback (WSS). Browser WebSocket clients can't set headers, so the token may be passed as a query param. Only over TLS, only with a short-lived access token, and don't log or persist the URL.

2 · API keys (M2M)

For programs/partners that should call the API without an interactive login, mint a long-lived, scoped key. The jk_… secret is used exactly like a JWT — as Authorization: Bearer jk_… (or ?token=jk_…) — on both GraphQL and WSS.

OperationSignature
Create (returns secret once)createApiKey(input: CreateApiKeyInput!): CreateApiKeyResult!
ListlistApiKeys: [ApiKey!]!
RevokerevokeApiKey(id: ID!): ApiKey!

CreateApiKeyInput: { name: String!, scopes: [String!]!, expiresAt? }. Scopes: terminal:read|write, sessions:read|write, plans:read|write (grant the minimum — a key is restricted to its scopes; a JWT is unrestricted). CreateApiKeyResult returns apiKey (metadata only) + secret (the jk_… value, shown once).

Bootstrapping. Creating a key is JWT-only (a key can't mint keys). So either the partner logs in once (Authentication) to create their own key, or you mint it for them in the Developer console — after that they use only the key.

Live terminal (WebSocket)

Connect to {{ wsBase }}/api/relay/ws with your token (JWT or jk_… key — see Access). The server validates the token, resolves your desktop node, and routes the socket. Messages are JSON envelopes: 

{ "type": "terminal_command", "data": { "requestId": "<uuid>", "sessionId": "<AiSession.id>", "data": "", "control": "visual_subscribe" } }

Client → server

typePayloadMeaning
terminal_command (visual_subscribe)data: { requestId, sessionId, data: "", control: "visual_subscribe" }Subscribe to future terminal_screen updates. (scope terminal:read)
terminal_command (visual_refresh)data: { requestId, sessionId, data: "", control: "visual_refresh" }Pull current screen (subscribe streams only future frames).
terminal_commanddata: { requestId, sessionId, data: "<input>" }Send keystrokes / input (data string, \r to submit). (scope terminal:write)
terminal_command (resize)data: { requestId, sessionId, data: { cols, rows } }Resize the terminal.
terminal_command (kill)data: { requestId, sessionId, data: "", control: "kill" }Terminate the terminal session.

Server → client

typePayloadMeaning
terminal_screen{ sessionId, data: <screen> }Current terminal screen contents. Sent on subscribe and on change.
terminal_command_ack{ sessionId, error? }Input was accepted (or error e.g. 'forbidden_session').
session_deleted / session_updated{ sessionId }Session lifecycle change.
agent_plan_run_updated{ data }A plan run advanced (phase/status change).
Ownership. You may only act on sessions your account owns; an envelope referencing another account's sessionId is rejected. You never send a node id — the server derives your node from the token.

Quickstart (Node.js)

Login → create a session → stream its terminal → send a command. Requires ws (and Node 18+ for fetch).

import WebSocket from 'ws';
const BASE = '{{ base }}';
const gql = (q, variables, token) => fetch(BASE + '/graphql', {
  method: 'POST',
  headers: { 'content-type': 'application/json', ...(token && { authorization: `Bearer ${token}` }) },
  body: JSON.stringify({ query: q, variables }),
}).then(r => r.json());

// 1. Login (JWT) — or skip and use a jk_ API key directly as the token below
const { data: { login } } = await gql(
  'mutation($i:LoginInput!){login(input:$i){accessToken refreshToken}}',
  { i: { email: 'you@partner.com', password: process.env.PW, tenantId: 'your-tenant' } });
const token = login.accessToken;

// 2. Create a session
const { data: { createAiSession: s } } = await gql(
  'mutation($i:CreateAiSessionInput!){createAiSession(input:$i){id}}',
  { i: { provider: 'claude_code', workingDirectory: '/home/you/project' } }, token);

// 3. Open the live terminal
const ws = new WebSocket(`${BASE.replace('https','wss')}/api/relay/ws`, {
  headers: { authorization: `Bearer ${token}` },   // or append ?token= in the URL
});
ws.on('open', () => {
  ws.send(JSON.stringify({ type: 'terminal_command', data: { requestId: 'sub1', sessionId: s.id, data: '', control: 'visual_subscribe' } }));
  ws.send(JSON.stringify({ type: 'terminal_command', data: { requestId: 'ref1', sessionId: s.id, data: '', control: 'visual_refresh' } }));
  ws.send(JSON.stringify({ type: 'terminal_command', data: { requestId: 'cmd1', sessionId: s.id, data: 'echo hello\r' } }));
});
ws.on('message', (buf) => {
  const msg = JSON.parse(buf.toString());
  if (msg.type === 'terminal_screen') console.log(msg.data);
});

A Python equivalent uses httpx/urllib for GraphQL and websockets for the socket — same envelopes.

Errors & limits

  • WebSocket upgrade rejected: 401 = missing/invalid token; 503 = no online desktop node for your account. Retry after re-authenticating / once the host is online.
  • GraphQL errors come back in the standard errors[] array (e.g. Authentication required for a missing/expired token).
  • Foreign session: an envelope or query for a session you don't own is rejected with error code forbidden_session.
  • Scope violation (API key): a scoped jk_* key without the needed scope returns FORBIDDEN_SCOPE (with scope) on WSS; GraphQL errors name the missing scope.
  • Token expiry mid-socket: the socket authenticates once at upgrade. When the access token nears expiry, refresh it and reconnect; re-subscribe after reconnect. Build in reconnect-with-backoff.

Versioning & forward-compat

The endpoint is unversioned and additive. Select only the fields you need; tolerate unknown enum values and extra response fields.

For errors use the real signals: GraphQL errors[].message text, WSS upgrade HTTP status 401/503, and in terminal_command_ack the .error ('forbidden_session' or 'FORBIDDEN_SCOPE'). RATE_LIMITED is reserved (not emitted in v1).

For AI agents

  • GraphQL is introspectable — run a standard introspection query against /graphql to get the full typed schema; you don't need to hardcode the operations above.
  • The WebSocket protocol is the only non-introspectable part — the envelope tables in Live terminal are the complete contract.
  • Start from the Quickstart — it's the full happy path (login → session → subscribe → command → read screen) in ~25 lines.
  • Identity is server-resolved — authenticate with the token only; never send a node id.
